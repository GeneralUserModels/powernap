## Moment Semantics

A moment is an accepted automation idea that produces a concrete artifact for the user.

Return structured JSON actions only. Python later renders promoted candidates into markdown files under `{tada_dir}/<topic>/<slug>.md`.

Cadence semantics:
- `once`: run once as soon as accepted.
- `scheduled`: run repeatedly according to `schedule`, such as `daily at 8am` or `Monday at 9am`.
- `trigger`: run when `trigger` evaluates true.

Use stable kebab-case slugs. Topics are kebab-case folder names. Create specific moments liberally when the entity, workflow, output, or user value is meaningfully distinct.

## Agent Capabilities For Completability Checks

Tasks are run by an execution agent with tools. The agent can browse authenticated sites with the user's cookies, run shell/code, do deep research, draft emails/docs, and produce static files. Outputs should be focused markdown pages under the requested research folder unless the task explicitly asks for another artifact.

The agent cannot build interactive backends, modify arbitrary files outside allowed locations, or create artifacts that call LLMs at runtime. Every run is one-shot: a daily digest means generate one digest now, not create a daemon or subscription.

## Moment Quality Bar

Prefer tasks that amplify the user and help with something they may do in the future: deep information foraging, preparation, comparison, exploratory experimentation, and extra-mile work the user would not do themselves. Strong moments extend one clear current trajectory, save time, reduce missed information, clarify a decision, make recurring work easier, or produce a concrete artifact the user can act on.

Reject ideas that are vague, generic, weakly evidenced, duplicative, broad productivity coaching, life summaries without a clear use, passive recaps with no next action, trivial tasks a human could do in a few minutes, or tasks requiring data that is unlikely to be available.
